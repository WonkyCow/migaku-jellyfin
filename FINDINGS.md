# Migaku x Jellyfin: technical findings

Notes from analysing Migaku extension **1.32.0.0** (re-verified against **1.32.1.0**) (read-only, from the author's own installed copy) to
add the Jellyfin web player as a supported site. Code is paraphrased, not reproduced. All of Migaku's
JS is minified onto a few very long lines, so "line references" are **character offsets** into the
named file (`python3 -c "print(open(F).read()[OFF:OFF+600])"`). Offsets are specific to 1.32.0.0.

Abbreviations: `DB` = `assets/dispatches.background-*.js`, `PS` = `assets/player-store-*.js`,
`MAIN` = `assets/main-*.js`, `CH` = `assets/core-host-*.js`, `BG` = `assets/background-script.ts-*.js`,
`UMD` = `assets/*.umd.cjs` (page-world "video website API" bundle).

> Migaku's Terms of Service restrict unofficial extensions and modifying its application. See the
> README's Legal / disclaimer section. These notes are technical documentation only.

## Architecture in one paragraph
Three cooperating parts: (1) an **isolated-world content script** (start + idle scripts, injected on
`<all_urls>`) that owns the UI, overlay and state; (2) a **page-world adapter bundle** (`UMD`) that
knows how to talk to each supported site's player; (3) a **core-host page and service worker** that
records tab audio and takes screenshots. (1) and (2) talk over DOM CustomEvents on `document`;
(1) and (3) talk over `chrome.runtime` messages.

## How Migaku decides a page is a supported video player
Hard-coded hostname/URL regexes, checked in four places:

| Gate | Where | Notes |
|---|---|---|
| Content scripts | `manifest.json` | start/idle run on `<all_urls>` (so Jellyfin already gets them). A `capture` script is YouTube-only. |
| Adapter injection | `DB` (`zin`, injector `bin`) | The page-world bundle is injected only if the hostname matches a table of regexes (`Z5`, keyed by site). |
| Domain / watch-URL tables | `DB` (`Z5` hostname table, `vy` watch-URL table) | `isVideoDomain` / `isVideoPage` in `PS` (`fS`) derive from `Object.values()` over these, so adding one entry to each makes a site "supported". |
| Adapter selection | tail of `UMD` (`EH`) | A chain `siteA() ? new A : siteB() ? new B : ... : localPlayer() ? new Local : null`. |

The patch adds a `JELLYFIN` entry to `Z5` and `vy` and one new branch at the head of the chain. Hosts come from
user configuration because self-hosted Jellyfin has no fixed domain.

### Adapter interface
Base class (`UMD`, class with `videoUrl=window.location.href;videoPlayer=null`). Subclasses must implement
`getVideoData`, `getVideoInfo`, `getSubtitle(meta, isTarget)`, `getMovieIdFromUrl`,
`awaitVideoToFinishLoading`, `hideVideoUI`, `displayVideoUI`. Overridable: `videoElementSelector`,
`standInSiblingSelector` / `standInContainerSelector` (where the subtitle-browser sidebar mounts),
`playerUiOverlayContainerSelector`, `getCurrentAudioTrack`, seek/play/pause helpers.
`getVideoPlayerData()` must yield `{videoHeight, videoWidth, playerBoundingRect, sidebar, sidebarWidth, pixelRatio, playbackRate}`.
The base class already provides a VTT-to-cue converter (`vttSubtitleToFullSubtitleData`), seek handling and
a hidden `<track>` helper (`addTrackElement`) that drives Migaku's cue-change events.

Subtitle track metadata Migaku expects: `{bestUrl, id, isNative, isClosedCaptions, isAutoGenerated, rawLanguage, language, languageDescription}`;
`getSubtitle` returns that object with a `subtitles` array added.

### Transport
Request: `CustomEvent("MigakuVideoInterfaceSend", {detail:{msgId, msgKey, payload}})` on `document`.
Reply: `CustomEvent("MigakuVideoInterfaceResponse", {detail:{msgId, msgKey, payload | error}})`.
Message keys look like `mgk--GetVideoData`, `mgk--GetSubtitles`, `mgk--GetVideoPlayerData`,
`mgk--SeekThenPlay`, `mgk--GetReadyState` (full list in `DB`). Default timeout 20 s, subtitle fetch 180 s.
Because both worlds share the DOM, an adapter can be exercised from DevTools by dispatching these events.

## Screenshot and audio capture
Non-YouTube sites use a **real-time tab recorder**, not ffmpeg cutting and not per-element capture:

1. Card creation (`PS`) arms recording, builds `playerData` from the adapter, then calls core-host
   `RECORD_SEGMENT {startTime, endTime, screenshot, playerData}` (audio padding comes from video options).
2. Arming = `START_TAB_RECORDING` -> `BG` -> `chrome.tabCapture.getMediaStreamId` -> core-host
   `getUserMedia({chromeMediaSource:"tab"})` -> `MediaRecorder` (`CH`). It requires the user to trigger the
   extension command once per tab (**Alt+R**), a Chrome `tabCapture`/`activeTab` rule.
3. Recording seeks the page's video to the cue start (`PLAY_VIDEO_FROM_TIME` -> adapter `SEEK_THEN_PLAY`),
   records in real time for `(end-start)/playbackRate`, and takes a screenshot at the midpoint.
4. Screenshot = `chrome.tabs.captureVisibleTab`, cropped to the video rectangle using `playerBoundingRect`,
   `videoWidth/Height`, `pixelRatio`. Output is `blob:` URLs wrapped as audio/image assets in the card payload.

The capture path is site-agnostic once an adapter exists. YouTube is special (separate SABR audio download).

## Telemetry observed (relevant to privacy)
Migaku's own code builds analytics events around recording (for example `record-video-seek-success`, sampled
at 10%, and `record-video-seek-error`, sampled at 100%). The payload includes the page's **domain name,
hostname and full URL** plus browser info. On Jellyfin that would be the Jellyfin server address. I confirmed
the payload and sampling but did not trace the transport, so treat this as "appears to report". This
project adds no telemetry of its own.

## What was built, and what it taught
- **Seam:** a page-world adapter in the existing chain, plus two regex-table entries and the injection gate.
  An outside script alone cannot work, because the hostname gate lives inside the extension.
- **Jellyfin data sources:** the web client's global `ApiClient`; the Sessions API returns the now-playing
  item, media source and selected audio/subtitle index (the `#/video` route has no item id). Subtitles come
  from `/Videos/{id}/{source}/Subtitles/{index}/0/Stream.vtt`, fetched with the client's own auth.
- **Layout bug and fix:** while the sidebar stand-in is active, Migaku forces the player container to
  `position: relative`. Jellyfin's player is normally fixed and full-viewport, so it collapsed to the video's
  aspect height and the OSD stayed full width under the sidebar. The adapter restores fixed positioning and
  publishes the container width as a CSS variable that sizes the OSD.
- **ASS tracks:** Jellyfin's converted VTT keeps ASS override codes (`{\i1}`, `\N`); the adapter strips them.
  Large anime tracks can be 10 MB+ with ~15k cues (typeset signs); filtering those is a possible improvement.
- **Overlay structure:** target and secondary subtitles are separate absolutely positioned lists
  (`.SubtitleOverlay__targetSubs`, `.SubtitleOverlay__secondarySubs`); position is draggable and stored; a
  background-shade opacity exists as a video option; size and hide toggles have default hotkeys. Only the
  order swap (secondary above target) is missing, which the adapter adds as **Alt+Shift+S** via CSS.
- **Shadow DOM:** Migaku's whole UI (toolbar, sidebar content, the subtitle overlay) lives in an **open** shadow
  root on `#MigakuShadowDom`. Page-level CSS cannot style anything inside it (measured: a page rule changed
  nothing, the same rule inside the shadow root changed a list's height as expected). Styling must be
  injected into `host.shadowRoot`, keyed on attributes of the host (`:host([attr]) ...`), and re-applied
  because Migaku re-renders.
- **Overlay geometry:** `.SubtitleOverlay__container` is positioned by an inline `bottom: max(<position>%, <px>)`
  and has zero height. Inside it, `.SubtitleOverlay__targetSubs` is absolutely positioned with its bottom edge
  at that anchor (it grows upward) and `.SubtitleOverlay__secondarySubs` with its top edge at the anchor (it
  grows downward). Putting the secondary line above the target therefore needs the target list's measured
  height; `bottom: 100%` alone resolves to the anchor and overlaps the target.
- **Local Player:** its adapter loads a `videoURL` string from a descriptor object, so a stream URL is plausible,
  but it has no UI for it and lives on the extension's own page; not pursued.

## Constraints and risks
- **Extension ID:** `manifest.json` has a `key`, so an unpacked copy has the **same ID** as the Store version;
  they cannot coexist in one profile. Use a separate profile.
- **In-place reload:** reloading an unpacked extension in place can leave it disabled (disable reason bit 24);
  restart the browser instead. A tab open at browser start may need one reload for Migaku to engage.
- **Version coupling:** minified identifiers change per release. The patch finds the ones it needs by pattern,
  gates on the tested version, and aborts if an anchor is missing or ambiguous.
- **Real-time capture:** card audio takes as long as the cue, and needs Alt+R once per tab.
- **Text subtitles only:** image or burned-in subtitles can't be read.
- **Terms of Service:** Migaku's Terms restrict unofficial extensions and modifying its application; see the
  README's disclaimer.
